## 서비스 성격

수기 장부로 관리되던 공장의 입고·출고·재고 현황을 디지털화하여 실시간으로 관리하는 웹 기반 재고관리 플랫폼입니다. 실제 현장 작업자가 PC와 태블릿 환경에서 재고 추이를 파악하고, 입출고 업무를 효율적으로 처리할 수 있도록 설계된 실무 중심의 도구입니다.

## 나의 역할

- **프론트엔드 전체 개발 (Vue.js) 및 아키텍처 설계**
- 현장 작업자의 사용성을 고려한 UI/UX 기획 및 디자인
- VueX 기반의 전역 상태 관리 및 데이터 동기화 로직 구현
- 대시보드(Chart.js)와 실무 페이지(Table)의 목적별 UI 차별화 구현

## 배경 및 문제

지인이 운영하는 공장에서는 모든 입·출고 데이터를 종이 장부와 엑셀에 의존해 관리하고 있었습니다. 이로 인해 다음과 같은 운영상의 비효율과 리스크가 존재했습니다.

- **데이터의 불투명성:** 현재 창고에 재고가 얼마나 있는지, 지난달 대비 출고량이 얼마나 늘었는지를 한눈에 파악하기 어려워 과다 발주나 재고 부족 사태가 빈번했습니다.
- **휴먼 에러의 위험:** 수기 기록 특성상 누락이나 오기입이 발생하기 쉽고, 월 마감 시점에 데이터가 맞지 않아 원인을 찾는 데 많은 시간을 허비했습니다.
- **현장 접근성 부족:** PC가 없는 창고 현장에서도 재고를 확인하거나 입력해야 하는 니즈가 있었으나, 기존 엑셀 방식으로는 불가능했습니다.

따라서 <strong>"누구나 별도의 교육 없이도 직관적으로 사용할 수 있고, 태블릿에서도 동작하는 웹 기반 관리 시스템"</strong>으로의 전환이 시급했습니다.

## 목표

- 종이 기록 업무를 100% 웹 기반으로 전환하여 업무 자동화 및 데이터 자산화
- **[대시보드]** 입·출고 흐름과 재고 현황을 한눈에 파악할 수 있는 시각화 화면 제공
- **[기능 페이지]** 입·출고 등록 및 관리는 테이블(Table) UI로 통일하여 데이터 처리 속도 확보
- '월 마감' 기능을 도입하여 데이터 조작 실수를 방지하고 재무적 정확성 확보
- PC와 태블릿(iPad 등) 해상도를 모두 지원하는 반응형 UI 구축

## 나의 기여

### 1) 목적에 따른 UI/UX 이원화 설계

사용자의 방문 목적에 따라 화면 구성을 철저히 분리하여 업무 효율을 높였습니다.

- **시각화 중심의 대시보드:** 접속 직후 보이는 홈 화면은 Chart.js를 활용해 일간 입·출고량, 인기 품목 등을 그래프로 시각화했습니다. 작업자가 "오늘 얼마나 바쁜지", "재고가 부족한 건 없는지" 흐름을 3초 안에 파악하도록 설계했습니다.
- **데이터 처리 중심의 기능 페이지:** 실제 입·출고 등록과 수정이 일어나는 페이지는 전면 테이블(Table) UI를 적용했습니다. 불필요한 그래픽을 배제하고, 한 화면에 최대한 많은 데이터를 표시하여 스크롤 없이도 빠르게 업무를 처리할 수 있게 만들었습니다.

### 2) 데이터 무결성을 위한 비즈니스 로직 구현

단순한 입력 도구를 넘어, 관리 시스템으로서의 신뢰도를 확보했습니다.

- **월 마감 시스템 구축:** 이미 정산이 끝난 과거 데이터가 실수로 수정되는 것을 막기 위해 '월 마감' 기능을 개발했습니다. 마감된 월의 데이터는 수정/삭제가 불가능하도록 프론트엔드단에서 방어 로직을 적용했습니다.
- **입력 검증 강화:** 수량에 음수가 입력되거나, 유효하지 않은 날짜가 들어가는 것을 폼 레벨에서 원천 차단하여 데이터 오염을 방지했습니다.

### 3) 현장 중심의 사용성 개선

IT 기기에 익숙하지 않은 작업자도 쉽게 쓸 수 있도록 진입 장벽을 낮췄습니다.

- **반응형 인터페이스:** 태블릿 환경에서도 테이블 데이터가 깨지지 않도록 가로 스크롤과 중요 정보 위주의 컬럼 배치를 적용하고, 터치하기 편한 버튼 크기(44px 이상)를 확보했습니다.
- **동선 최적화:** 작업자가 자주 쓰는 '등록' 버튼을 화면 우측 하단에 플로팅(Floating) 버튼으로 배치하여, 긴 테이블을 스크롤하다가도 즉시 기능에 접근할 수 있게 만들었습니다.

### 4) VueX 기반의 효율적인 상태 관리

- **데이터 동기화:** 입고 페이지(Table)에서 데이터를 추가하면, 대시보드(Chart)의 재고 현황이 즉시 갱신되도록 VueX로 데이터를 전역 관리했습니다. 이를 통해 사용자가 새로고침 없이도 항상 최신 데이터를 볼 수 있는 반응성 높은 경험을 제공했습니다.

## 문제 해결

### 1) 방대한 데이터 조회 시의 가독성 및 효율성 문제

- **문제:** 모든 페이지에 차트와 테이블을 섞어서 배치할 경우, 한눈에 흐름을 보기도 어렵고 데이터를 입력하기도 불편한 이도 저도 아닌 UI가 될 우려가 있었음.
- **해결:** 화면의 역할을 명확히 분리. <strong>'보는 화면(대시보드-차트)'</strong>과 <strong>'하는 화면(입출고 관리-테이블)'</strong>로 나누어, 관리자는 흐름을 보고 실무자는 빠르게 데이터를 입력하는 최적의 동선을 구축.

### 2) 과거 데이터 오수정으로 인한 정산 불일치

- **문제:** 작업자가 실수로 지난달의 출고 수량을 수정해버려, 월말 결산 금액이 틀어지는 사고 발생.
- **해결:** 회계 시스템의 개념을 차용해 '마감(Closing)' 기능을 도입. 마감 버튼을 누르면 해당 월의 데이터는 'Read-only' 상태로 전환되도록 권한 로직을 설계하여 데이터 안정성 확보.

### 3) 태블릿 환경에서의 테이블 조작 불편함

- **문제:** PC 기준으로 설계된 넓은 테이블이 태블릿의 좁은 폭에서는 잘리거나, 스크롤이 불편해 작업 속도가 저하됨.
- **해결:** 태블릿 해상도 감지 시 테이블의 불필요한 컬럼(등록일시 등)은 숨기고 핵심 정보(품명, 수량) 위주로 보여주는 반응형 테이블을 구현하여 가독성을 확보.

## 성과 및 영향

- **성공적인 디지털 전환(DX):** 종이 장부와 엑셀을 완전히 대체하여, 공장 내 모든 재고 관리가 웹 시스템 하나로 통합됨.
- **운영 효율 및 정확도 향상:** 대시보드로 실시간 흐름 파악이 가능해지고, 테이블 기반의 빠른 입력과 마감 기능 덕분에 월말 정산 시간이 획기적으로 단축됨.
- **사용자 중심 UI 설계:** "예쁜 화면"보다 "목적에 맞는 화면(차트 vs 테이블)"이 실무에서 훨씬 중요하다는 UX 원칙을 확인하고 적용함.

## 배운 점

- **UI의 목적성:** 같은 데이터라도 '관제'가 목적일 때는 차트가, '관리'가 목적일 때는 테이블이 적합하다는 것을 깨닫고, 상황에 맞는 UI 패턴을 결정하는 안목을 길렀습니다.
- **데이터 신뢰성의 가치:** 사용자가 믿고 쓸 수 있는 시스템이 되기 위해서는 프론트엔드단에서도 데이터 무결성을 위한 방어 코드(마감, 검증)가 필수적임을 체감했습니다.
