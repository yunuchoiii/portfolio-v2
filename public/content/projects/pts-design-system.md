## 서비스 성격

사내 웹뷰 서비스(WithPTS, PartTimeStudy) 구축을 본격화하기 전, 일관된 UI/UX 제공과 개발 생산성을 위해 선제적으로 구축한 React 기반 디자인 시스템 라이브러리입니다.

## 나의 역할

- 입사 후 첫 프로젝트로 디자인 시스템 전체 설계 및 로드맵 수립
- shadcn UI + Radix 기반의 공통 컴포넌트 커스터마이징 및 구현
- 웹뷰 환경에서의 체감 성능 향상을 위한 마이크로 인터랙션 설계 및 구현
- 정적 디자인 시안에 없는 UX 요소를 기획/디자인 팀에 역제안하여 고도화

## 배경 및 문제

입사 직후 회사에서는 여러 웹뷰 프로젝트가 예정되어 있었으나, 네이티브 앱에 비해 상대적으로 낮은 성능과 반응성으로 인해 사용자 경험이 저해될 우려가 있었습니다. 또한 본격적인 개발 전 다음과 같은 문제점들이 식별되었습니다.

- **웹뷰의 한계와 낮은 체감 성능:** 네이티브 앱 대비 터치 반응이 둔탁하거나 화면 전환이 매끄럽지 않아, 사용자가 '웹사이트'라고 느끼는 순간 몰입도가 깨질 위험이 컸습니다.
- **인터랙션 명세의 부재:** 전달받은 디자인 시안은 정적인 이미지 위주여서, 버튼을 눌렀을 때의 피드백이나 모달이 뜰 때의 움직임 등 '사용자 경험의 질'을 결정하는 동적인 요소가 정의되어 있지 않았습니다.
- **반복 작업과 파편화:** 공통 기준 없이 각자 개발할 경우 리소스 낭비는 물론, 프로젝트마다 UI 동작이 달라져 브랜드 경험을 해칠 가능성이 높았습니다.

따라서 저는 <strong>"네이티브 앱 수준의 자연스러운 인터랙션을 포함한 공통 UI 시스템"</strong>을 먼저 구축하여, 이후 개발될 모든 서비스가 기술적 한계를 넘어 뛰어난 사용자 경험을 제공할 수 있도록 기반을 다져야 한다고 판단했습니다.

## 목표

- 웹뷰의 성능 한계를 극복하고 사용자에게 직관적인 반응을 주는 인터랙션 시스템 구축
- 정적인 디자인을 넘어, 동적인 사용성까지 포함된 공통 UI 컴포넌트 자산 확보
- npm 패키지 배포를 통해, 향후 생성될 모든 프로젝트가 즉시 UI 라이브러리를 사용할 수 있는 환경 조성
- 기획/디자인 단계에서 놓친 UX 디테일을 개발 단계에서 선제적으로 보완

## 나의 기여

### 1) 웹뷰 한계를 극복하는 인터랙션 주도적 설계 및 구현

디자인 시안에는 명시되지 않았으나, 사용자 경험 향상을 위해 필수적이라고 판단되는 인터랙션을 직접 설계하고 디자이너와 소통하여 구현했습니다.

- **체감 성능(Perceived Performance) 향상:** 웹뷰 특유의 딜레이를 감추기 위해, 버튼 탭 시 즉각적인 시각적 피드백(Opacity, BackgroundColor 등)을 주고 스켈레톤 UI와 로딩 인터랙션을 정교화하여 시스템이 즉시 반응하고 있다는 느낌을 전달했습니다.
- **직관적인 모션 디자인:** 바텀 시트나 모달이 켜질 때 단순히 나타나는 것이 아니라, 물리 법칙을 고려한 부드러운 스프링 애니메이션을 적용해 사용자가 UI의 흐름을 자연스럽게 이해하도록 유도했습니다.

### 2) 사용자 중심의 컴포넌트 커스터마이징 (shadcn UI + Radix)

오픈 소스인 shadcn UI를 기반으로 하되, 모바일 웹뷰 환경에 맞춰 재설계했습니다.

- **모바일 네이티브 경험 이식:** 터치 영역을 충분히 확보하고, 제스처 기반의 닫기 동작 등을 추가하여 앱과 이질감 없는 사용성을 제공했습니다.
- **접근성 강화:** 스크린 리더 지원 및 키보드 네비게이션을 보장하여 다양한 환경의 사용자도 불편함 없이 사용할 수 있도록 기본기를 다졌습니다.

### 3) 확장성을 고려한 npm 패키지 배포 구조 설계

- **즉시 사용 가능한 배포 파이프라인:** `npm install` 한 번으로 디자인 시스템을 바로 적용할 수 있게 하여, 신규 프로젝트 세팅 시간을 획기적으로 단축시켰습니다.
- **중앙 집중식 UX 관리:** UI 버그 수정이나 사용성 개선 업데이트가 필요할 때, 라이브러리 버전만 올리면 모든 프로젝트에 일괄 적용되는 효율적인 유지보수 체계를 마련했습니다.

## 문제 해결

### 1) 디자인 시안의 '인터랙션 공백'을 개발자 관점에서 해결

- **문제:** 디자이너가 전달한 시안은 정적인 화면(Static View)뿐이라, 실제 구현 시 밋밋하고 조작감이 떨어지는 웹 페이지처럼 느껴짐.
- **해결:** "사용자는 멈춰있는 화면이 아니라 움직이는 앱을 쓴다"는 점을 강조하며, 디자이너에게 버튼 클릭감, 트랜지션 효과 등을 역제안. 협의를 통해 마이크로 인터랙션을 표준화하여 시스템에 반영함.

### 2) 웹뷰의 느린 반응 속도로 인한 사용자 답답함 해소

- **문제:** 네이티브 앱에 비해 터치 후 반응까지 미세한 지연이 발생해 사용자가 시스템을 신뢰하지 못하는 느낌을 줌.
- **해결:** 시각적 피드백(Active State)을 터치와 동시에 발생하도록 최적화하고, 데이터 로딩 중에도 부드러운 전환 효과를 유지하여 사용자가 '느리다'고 인지하지 못하게끔 체감 성능을 개선함.

### 3) 파편화된 UI 구현 방지 및 일관성 확보

- **문제:** 프로젝트마다 개발자가 임의로 UI를 구현할 경우 UX 차이가 발생하여 사용자 경험을 해칠 우려가 있었음.
- **해결:** 서비스 개발 착수 전 공통 컴포넌트를 먼저 배포하여, 모든 개발자가 표준화된 블록을 사용하게 함으로써 100% 일관된 사용자 경험을 보장.

## 성과 및 영향

- **"앱 같은 웹" 구현의 기술적 기반 마련:** 인터랙션이 가미된 컴포넌트 덕분에 웹뷰 서비스임에도 네이티브 앱 수준의 매끄러운 사용성을 확보.
- **성공적인 신규 프로젝트 런칭 가속화:** 디자인 시스템 구축 직후 시작된 WithPTS, PartTimeStudy 프로젝트의 초기 UI 개발 시간을 약 40% 단축.
- **디자인-개발 협업 프로세스 진화:** 개발자가 단순히 시안을 옮기는 것을 넘어, UX 개선을 위한 인터랙션을 제안하는 능동적인 협업 문화가 형성됨.

## 배운 점

- 개발자는 단순히 디자인을 코드로 옮기는 사람이 아니라, **기술을 통해 디자인의 빈틈을 채우고 사용자 경험을 완성하는 사람**임을 깨달았습니다.
- 웹뷰 환경에서 인터랙션이 단순한 시각적 장식이 아니라, 성능 한계를 극복하고 사용자에게 신뢰를 주는 핵심 기능임을 배웠습니다.
