## 서비스 성격

파트타임스터디 앱의 핵심 기능(캐릭터 성장, 스터디 그룹 등)을 네이티브 앱과 동일한 사용자 경험으로 제공하기 위해 구축한 하이브리드 웹뷰 서비스입니다.

## 나의 역할

- 웹뷰 초기 아키텍처 설계 및 앱과 웹 통신을 위한 브릿지 프로토콜 구현
- 핵심 기능(스터디 그룹)의 초기 기획, 와이어프레임 설계 및 전담 개발
- 네이티브 앱 수준의 조작감과 안정성을 확보하기 위한 UX 및 렌더링 최적화
- React Query 기반의 데이터 상태 관리 및 핵심 비즈니스 로직 개발
- 사내 디자인 시스템 라이브러리를 적용하여 일관된 UI 구현

## 배경 및 문제

앱 서비스의 특성상 작은 UI 수정이나 A/B 테스트를 하려 해도 앱 스토어 심사와 배포 과정을 거쳐야 했기에, 사용자 피드백을 반영하는 주기가 지나치게 길었습니다. 이는 급변하는 사용자 니즈를 맞추기에 치명적인 단점이었습니다. 이를 해결하기 위해 웹뷰 도입이 결정되었으나, 당시 팀 내에는 웹뷰 구축 경험과 기준이 전무하여 다음과 같은 우려가 있었습니다.

- **이질적인 사용자 경험:** 웹뷰가 단순히 '앱 안에 뜬 웹페이지'처럼 느껴질 경우, 앱 전체의 완성도가 떨어져 보이고 사용자 몰입을 방해할 위험이 있었습니다.
- **기술적 기반 부재:** 앱과 웹이 어떻게 데이터를 주고받을지에 대한 표준 프로토콜이 없어, 개발자마다 다른 방식으로 구현할 경우 잦은 오류가 예상되었습니다.
- **플랫폼 파편화:** iOS와 Android의 웹뷰 동작 방식이 달라, 이를 통합 제어하지 않으면 사용자에게 엉성한 UI를 보여줄 수밖에 없었습니다.

따라서 단순한 기능 구현을 넘어, <strong>"사용자가 웹뷰임을 인지하지 못할 정도로 자연스럽고 안정적인 환경"</strong>을 만드는 것이 최우선 과제였습니다.

## 목표

- 네이티브 앱 기능처럼 매끄럽게 동작하는 고품질 웹뷰 서비스 구축
- 앱과 웹 간의 데이터 통신을 안전하고 일관되게 처리하는 브릿지 시스템 정립
- iOS 및 Android 각 플랫폼 특성을 기술적으로 흡수하여 사용자에게 동일한 UX 제공
- 디자인 시스템 및 React Query 도입으로 유지보수가 용이하고 확장 가능한 코드 구조 마련

## 나의 기여

### 1) 기능 오너십 발휘: 스터디 그룹 기획 및 개발

개발 단계 이전부터 주도적으로 참여하여 기능의 완성도를 높였습니다.

- **주도적 기획 및 와이어프레임 설계:** 스터디 그룹 기능의 초기 컨셉을 구체화하여 와이어프레임을 직접 설계했고, 이를 바탕으로 기획자와 논의하며 비즈니스 로직을 확정했습니다.
- **협업 효율 증대:** 개발자가 먼저 구조를 잡은 와이어프레임을 디자이너에게 전달하여, 디자인 단계에서의 시행착오를 줄이고 개발 구현 가능성을 고려한 최종 UI가 나오도록 리드했습니다.

### 2) 앱과 웹 통합 브릿지 아키텍처 설계 및 구현

웹뷰 도입의 첫 단추인 '통신' 구조를 바닥부터 설계했습니다.

- **안전한 핸드쉐이크:** 앱 진입 시 인증 토큰 교환, 초기화 신호, 네비게이션 제어 등을 순차적으로 처리하는 프로토콜을 만들어, 로그인 풀림이나 데이터 로드 실패 같은 치명적인 사용자 경험을 사전에 차단했습니다.
- **플랫폼 추상화:** iOS와 Android의 서로 다른 통신 방식을 하나의 인터페이스로 묶어, 비즈니스 로직 개발 시 플랫폼 차이를 신경 쓰지 않아도 되도록 구조화했습니다.

### 3) 네이티브 수준의 UX 디테일 완성

"웹이라서 어쩔 수 없다"는 기술적 한계를 사용자 경험 관점에서 극복했습니다.

- **뷰포트 및 레이아웃 안정화:** 모바일 브라우저의 주소창이나 키보드 노출로 인한 화면 덜컥거림을 막기 위해 dvh, svh 단위를 적극 활용하고 레이아웃 리플로우를 제어했습니다.
- **즉각적인 피드백 구현:** 터치 딜레이를 제거하고, 스켈레톤 UI를 적용하여 데이터 로딩 중에도 화면이 멈춘 것처럼 보이지 않도록 '체감 속도'를 높였습니다.

### 4) React Query 기반의 탄탄한 데이터 흐름 구축

불안정한 모바일 네트워크 환경을 고려하여 데이터 관리 전략을 수립했습니다.

- **캐싱 전략 최적화:** staleTime과 캐싱을 적절히 활용하여 페이지 이동 시 불필요한 API 호출을 줄였습니다. 이는 데이터 로딩 시간을 단축시켜 사용자에게 쾌적한 탐색 경험을 제공했습니다.

## 문제 해결

### 1) 통신 규약 부재로 인한 데이터 유실 및 오류 방지

- **문제:** 초기에는 앱과 웹이 서로 보낸 신호를 제때 받지 못해, 화면은 떴는데 데이터가 없거나 로그인이 안 되는 간헐적 오류가 발생할 위험이 큼.
- **해결:** 양방향 통신 규약을 문서화하고, 모든 통신을 중앙 브릿지 모듈을 거치도록 일원화. 그 결과 초기 진입 성공률과 통신 안정성을 100% 가깝게 확보하여 사용자 신뢰도 유지.

### 2) 웹뷰 특유의 이질감(화면 흔들림, 터치감) 해소

- **문제:** iOS에서 스크롤 시 바운스 효과가 생기거나, 입력창 포커스 시 화면이 확대/축소되는 등 '웹사이트스러운' 동작이 사용자 경험을 저해.
- **해결:** CSS의 overscroll-behavior 제어, 뷰포트 메타 태그 최적화, 터치 영역 보정 등을 통해 네이티브 앱과 구분이 가지 않는 단단한 조작감 구현.

### 3) 웹뷰 성능 및 안정성에 대한 우려 불식

- **문제:** "웹뷰는 느리고 버그가 많다"는 내부 우려와 성능 저하 가능성.
- **해결:** 렌더링 최적화와 효율적인 상태 관리를 통해 앱보다 가벼운 구동 속도를 증명. 실제로 오픈 후 네이티브 영역보다 CS 발생 건수가 현저히 적은 안정적인 서비스를 운영함.

## 성과 및 영향

- **성공적인 하이브리드 앱 전환:** 첫 웹뷰 도입임에도 불구하고 이질감 없는 고품질 UX를 구현하여 서비스에 성공적으로 안착.
- **운영 효율성 극대화:** 앱 심사 없이 즉시 배포 가능한 환경을 구축하여, 버그 수정 및 UI 개선 속도가 기존 대비 획기적으로 빨라짐.
- **높은 서비스 안정성:** 앱 대비 오류 발생률이 낮고 CS 인입이 적어, "웹뷰도 잘 만들면 네이티브만큼 훌륭하다"는 인식을 팀 내에 심어줌.

## 배운 점

- **기획 단계 참여의 중요성:** 와이어프레임 설계부터 참여하니 개발 단계에서의 불확실성이 줄어들고, 결과적으로 더 완성도 높은 프로덕트가 나온다는 것을 체험했습니다.
- **사용자 경험의 본질:** 사용자는 기술 스택에 관심이 없으며, 오직 '끊김 없고 자연스러운 경험'만을 원한다는 본질을 깨닫고, 이를 위해 기술적 난제들을 집요하게 파고드는 태도를 길렀습니다.
