## 서비스 성격

- 루틴 인증과 습관 형성을 게이미피케이션으로 풀어낸 하이브리드 모바일 앱입니다.
- 사용자가 루틴을 달성하며 얻은 보상으로 아일랜드를 성장시키고, 팀원들과 실시간으로 소통하며 동기부여를 얻는 소셜 서비스입니다.

## 나의 역할

- **React Native**와 **Next.js**를 활용한 하이브리드 앱 아키텍처 설계 및 전 영역 개발 주도
- 안정적인 앱-웹 데이터 교환을 위한 **Native-Web Bridge** 메시징 시스템 구축
- <strong>TanStack Query(React Query)</strong>의 **Optimistic Update**를 활용한 실시간 인터랙션 구현
- **OAuth 2.0** 멀티 소셜 로그인 및 **FCM** 기반 푸시 알림 인프라 통합 연동

## 배경 및 문제

하이브리드 앱 특성상 네이티브와 웹뷰 사이의 경계에서 사용자 경험이 단절될 우려가 컸습니다. 특히 실시간 리워드 획득처럼 즉각적인 반응이 중요한 기능에서 발생하는 네트워크 지연은 서비스의 몰입도를 저해하는 핵심 문제였습니다.

- **앱-웹 전환의 이질감:** 로그인이나 알림 클릭 시 세션 동기화가 지연되어 사용자가 반복적으로 로그인을 마주할 위험이 있었습니다.
- **낮은 반응성:** 리워드 버튼을 누를 때마다 서버 응답을 기다려야 하는 구조는 게임적인 쾌감을 반감시켰습니다.
- **리소스 관리의 복잡성:** 네이티브의 FCM 토큰과 웹의 유저 상태를 일관되게 유지해야 하는 기술적 난이도가 존재했습니다.

그래서 저는 <strong>"네이티브 수준의 반응성과 웹의 유연함이 공존하는 끊김 없는 경험"</strong>을 목표로, 견고한 통신 규격과 선제적 UI 반영 시스템을 구축했습니다.

## 목표

- 네이티브와 웹뷰 간의 경계가 느껴지지 않는 **Seamless Hybrid UX** 환경 구축
- **Optimistic Update**를 통해 조작 즉시 반응하는 네이티브 수준의 인터랙션 구현
- **FCM 토큰 관리 자동화**로 높은 알림 도달률 및 딥링크 사용성 확보

## 나의 기여

### 1) 타입 안정성을 갖춘 전용 Bridge 시스템 설계

네이티브와 웹뷰가 서로 다른 환경임에도 유기적으로 작동하도록 **TypeScript 기반의 브릿지 프로토콜**을 구축했습니다.

- **양방향 메시징 인터페이스:** 햅틱 피드백, 외부 브라우저 호출 등 네이티브 기능을 웹뷰에서 타입 안전하게 호출할 수 있는 표준 규격을 만들었습니다.
- **실패 방지 핸들링 도입:** 웹뷰 로딩 완료 전 전송된 메시지가 유실되지 않도록 **재시도 메커니즘**을 적용하여 통신 안정성을 확보했습니다.

### 2) 성능 최적화 패턴을 통한 게이미피케이션 최적화

사용자의 액션에 즉각적으로 반응하는 앱을 만들기 위해 성능 최적화 기법을 적극적으로 도입했습니다.

- **체감 성능 극대화:** 별/응원 클릭 시 서버 응답 전 UI를 먼저 업데이트하여 **네트워크 지연 시간(평균 1s)을 체감상 0ms로 단축**했습니다.
- **트래픽 최적화:** 연타가 잦은 리워드 시스템에 1초 단위의 **Debouncing**을 적용, 여러 건의 클릭을 단일 API 요청으로 병합하여 서버 부하를 효율적으로 줄였습니다.

### 3) 하이브리드 통합 인증 및 FCM 인프라 구축

- **통합 세션 관리:** 4개 소셜 로그인 플랫폼을 네이티브 SDK로 연동하고, 획득한 토큰을 **Keychain**에 저장한 뒤 웹뷰 세션과 실시간 동기화하여 중복 로그인 문제를 해결했습니다.
- **FCM 및 딥링크 자동화:** 앱 라이프사이클에 맞춰 토큰을 자동 갱신하고, 알림 클릭 시 딥링크를 통해 특정 화면으로 즉시 진입하는 유입 경로를 확보했습니다.

## 문제 해결

### 1) 하이브리드 환경의 '인증 세션 파편화' 해결

- **문제:** 앱 로그인 후 웹뷰 진입 시 세션이 즉시 반영되지 않아 다시 로그인 화면이 노출되는 이슈가 있었습니다.
- **해결:** 웹뷰 로딩 직전 네이티브에서 토큰을 선제적으로 주입하고, 브릿지를 통해 인증 상태 변화를 실시간으로 전파하여 **앱-웹 간 단일 인증(SSO) 환경**을 구현했습니다.

### 2) 실시간 리워드 획득 시의 데이터 무결성 보장

- **문제:** 버튼을 빠르게 연타할 때 API 응답 순서가 뒤섞여 UI 숫자가 비정상적으로 튀는 현상이 발생했습니다.
- **해결:** **Query Key 취소(Cancel Queries)** 전략을 강화하여 새로운 요청이 발생하면 이전 요청을 무시하고 최종 상태만 보장함으로써 시각적 오류를 원천 차단했습니다.

### 3) 웹뷰 초기 로딩 시의 시각적 노이즈 제거

- **문제:** 웹뷰 로딩 전 찰나의 하얀 배경이 노출되어 하이브리드 앱 특유의 이질감이 느껴졌습니다.
- **해결:** 네이티브 스플래시 화면을 웹뷰의 **데이터 하이드레이션(Hydration) 완료 시점**까지 유지하는 플래그 시스템을 도입하여 네이티브 앱과 동일한 진입 경험을 제공했습니다.

## 성과 및 영향

- **사용자 만족도 상승:** 낙관적 업데이트 적용 후 리워드 참여도가 대폭 상승하며 게이미피케이션의 목적을 달성했습니다.
- **개발 생산성 향상:** 표준화된 Bridge 라이브러리 구축으로 신규 네이티브 연동 기능 개발 시간을 **50% 이상 단축**했습니다.
- **리텐션 기여:** FCM 토큰 동기화 로직 최적화로 푸시 알림 도달률과 사용자 재방문율을 안정적으로 유지했습니다.

## 배운 점

- **사용자 경험으로서의 성능:** 하이브리드 앱에서 성능은 코드의 효율성을 넘어, 적절한 UI 패턴을 통해 사용자에게 신뢰를 주는 디자인적 장치임을 배웠습니다.
- **규약 정의의 중요성:** 서로 다른 기술 스택을 잇는 과정에서 타입 시스템을 통한 엄격한 규약 정의가 프로젝트의 안정성에 얼마나 큰 기여를 하는지 실감했습니다.
