## 서비스 성격

학원 소개, 강사진, 커리큘럼 정보를 제공하고 학부모 상담 문의를 접수하는 학원 브랜딩 웹사이트입니다. 단순 정적 페이지를 넘어, Node.js로 백엔드 서버를 직접 구축하여 상담 데이터 처리와 API 통신의 전 과정을 구현한 풀스택 프로젝트입니다.

## 나의 역할

- 기획·디자인·개발·배포 등 웹사이트 제작 전 과정 1인 수행
- Next.js 및 TailwindCSS 기반의 반응형 프론트엔드 개발
- Node.js(Express) 기반의 백엔드 서버 및 API 엔드포인트 구축
- 검색 엔진 최적화(SEO) 전략 수립 및 적용

## 배경 및 문제

학원 개원 초기, 학부모들이 정보를 얻을 수 있는 공식 채널이 부재하여 신뢰도를 형성하는 데 어려움이 있었습니다.

- **학부모의 정보 탐색 피로도:** 학부모들은 '어떤 선생님이 가르치는지', '커리큘럼은 어떤지'를 즉시 확인하고 싶어 하지만, 정보가 분산되어 있어 전화 상담 외에는 확인할 방법이 없었습니다. 이는 잠재 고객의 이탈로 이어졌습니다.
- **낮은 온라인 접근성:** 지역 기반 학원임에도 포털 사이트 검색 시 노출되지 않아, 자연 유입을 통한 신규 원생 모집이 불가능했습니다.
- **프론트엔드 개발의 한계 극복 니즈:** 지금까지 클라이언트 개발에 집중해왔으나, 데이터가 서버로 넘어가고 처리되는 전체 라이프사이클을 직접 다뤄보며 '백엔드 개발자의 관점'을 이해하고자 하는 기술적 목표가 있었습니다.

따라서 <strong>"학부모가 궁금한 정보를 가장 빠르게 해소해주고 상담으로 연결하는 UX"</strong>를 설계함과 동시에, <strong>"서버부터 클라이언트까지 혼자서 완결 짓는 경험"</strong>을 쌓기로 결정했습니다.

## 목표

- 학원을 처음 접하는 학부모에게 신뢰감을 주고 상담 전환율을 높이는 UI/UX 설계
- 광고비 집행 없이 기술적 최적화(SEO)만으로 지역 키워드 검색 상위 노출 달성
- Node.js로 백엔드 로직을 직접 구현하여 웹 서비스의 전체 데이터 흐름(Full-Cycle) 체득
- PC와 모바일 모든 환경에서 최적화된 반응형 웹 구현

## 나의 기여

### 1) 학부모의 니즈를 반영한 정보 구조 및 UX 설계

사용자(학부모)가 웹사이트에 방문하는 목적을 분석하여 불필요한 뎁스를 줄였습니다.

- **핵심 정보 우선 배치:** '인사말 -> 강사진 -> 커리큘럼 -> 오시는 길'의 순서로, 학부모가 의사결정을 내리기 위해 필요한 정보 순서대로 레이아웃을 구성했습니다.
- **즉각적인 연결 경험:** 어느 페이지를 보고 있더라도 궁금증이 생기면 바로 문의할 수 있도록 전화 및 카카오톡 상담 CTA(Call To Action) 버튼을 화면 하단에 고정 배치했습니다.

### 2) 기술적 SEO(검색 엔진 최적화)를 통한 마케팅 비용 절감

마케팅 예산 없이도 타겟 고객에게 노출되도록 코드를 최적화했습니다.

- **시맨틱 구조화:** 검색 엔진 봇이 콘텐츠를 잘 이해할 수 있도록 `header`, `main`, `section` 등 시맨틱 태그를 적재적소에 활용했습니다.
- **동적 메타데이터 관리:** Next.js의 Metadata API를 활용하여, '노원구 수학학원', '초중등 수학' 등 지역 타겟 키워드가 검색 결과에 매력적으로 노출되도록 Title과 Description을 정교하게 설계했습니다.

### 3) Node.js 백엔드 서버 직접 구축 (Technical Challenge)

프론트엔드 영역을 넘어 백엔드 서버를 직접 구축하며 기술적 시야를 넓혔습니다.

- **API 서버 구현:** Express.js를 사용하여 상담 요청 데이터를 받고 처리하는 API 엔드포인트를 직접 설계하고 개발했습니다.
- **데이터 흐름의 이해:** 클라이언트의 요청(Request)이 서버에 도달하고, 로직을 거쳐 응답(Response)으로 돌아오는 전체 과정을 구현하며 HTTP 통신, 상태 코드, CORS 이슈 등을 깊이 있게 이해했습니다. 이 경험은 이후 복잡한 웹뷰-앱 통신 및 API 연동 협업 시 백엔드 로직을 추론하는 데 큰 자산이 되었습니다.

## 문제 해결

### 1) 모바일 위주의 학부모 사용 패턴을 고려한 UI 개선

- **문제:** 초기 기획 시 PC 화면 위주로 정보를 나열했으나, 실제 학부모들은 90% 이상 이동 중에 모바일로 접속한다는 점을 간과함.
- **해결:** Mobile First 전략으로 선회. 작은 화면에서도 가독성을 해치지 않도록 폰트 크기와 줄 간격을 조정하고, 터치하기 편한 버튼 크기(44px 이상)를 적용하여 모바일 사용성을 극대화.

### 2) 신생 사이트의 검색 노출 불가 문제

- **문제:** 사이트 개설 직후에는 검색 엔진에 전혀 노출되지 않아, 학원 이름을 검색해도 찾을 수 없는 '유령 사이트' 상태였음.
- **해결:** Next.js의 SSR(Server Side Rendering) 특성을 활용해 검색 엔진 봇이 페이지 내용을 쉽게 긁어가도록 만들고, 지역명+과목명을 조합한 롱테일 키워드 전략을 본문에 녹여냄. 결과적으로 광고비 0원으로 구글/네이버 지역 검색 최상단을 점유.

### 3) 프론트엔드 개발자의 백엔드 이해도 부족

- **문제:** 이전까지는 API 명세서만 보고 연동했기에, 서버 내부에서 어떤 처리가 일어나는지 구체적으로 알지 못해 에러 핸들링이 수동적이었음.
- **해결:** Node.js로 서버를 직접 띄우고 배포까지 해보면서 환경변수 관리, 미들웨어 처리 등을 경험. 이를 통해 "서버가 왜 이런 에러를 보내는지"를 구조적으로 이해하게 되었고, 이후 프로젝트에서 백엔드 개발자와의 소통 비용을 크게 줄임.

## 성과 및 영향

- **압도적인 검색 노출 달성:** 별도 광고 없이 '지역명 + 수학학원' 키워드 검색 시 구글 및 네이버 최상단 노출 유지.
- **상담 전환율 상승:** 직관적인 정보 구조와 모바일 최적화 덕분에 웹사이트를 통한 전화 및 카카오톡 문의 유입 활성화.
- **풀스택 개발 경험 확보:** 기획부터 디자인, 프론트엔드, 백엔드, 배포까지 웹 서비스의 A to Z를 혼자 완수하며 개발자로서의 기술적 자신감과 전체를 보는 눈을 기름.

## 배운 점

- **코드의 마케팅 가치:** 잘 짜인 HTML 구조와 SEO 세팅이 수백만 원의 광고비를 아껴줄 수 있다는 사실을 체감하며, 기술이 비즈니스 성과에 직접 기여하는 방법을 배웠습니다.
- **백엔드 경험의 중요성:** 비록 간단한 로직이라도 서버를 직접 만져본 경험이, 프론트엔드 개발자가 API를 설계하고 연동할 때 얼마나 큰 안정감을 주는지 깨달았습니다.
