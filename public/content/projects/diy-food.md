## 서비스 성격

사용자가 자신의 예산과 건강 목표에 맞춰 **주도적으로 식재료와 메뉴를 선택하고 식단을 계획**할 수 있도록 돕는 웹 기반 식단 관리 서비스입니다. 공공데이터를 활용해 실시간 식재료 시세와 영양 정보를 제공하여, 경제적이고 건강한 식단 구성을 지원합니다.
**2022년 공개 소프트웨어 개발자 대회에서 동상을 수상**하며 기술적 완성도와 실용성을 인정받은 프로젝트입니다.

## 나의 역할

- **Frontend Lead:** Vue.js 기반의 SPA(Single Page Application) 아키텍처 설계 및 전체 기능 구현
- **UI/UX Design:** 서비스 기획, 와이어프레임 작성, GUI 디자인, 로고 제작 등 비주얼 작업 전담
- **Data Visualization:** Chart.js를 활용한 영양소 분석 및 물가 변동 추이 시각화
- **API Integration:** KAMIS(유통공사), 식품안전나라 등 Open API 데이터 전처리 및 연동

## 배경 및 문제

식단 관리를 결심한 사용자들은 스스로 식단을 짜고 싶어 하지만, "내가 고른 이 재료가 예산 안일까?", "영양소는 충분할까?"를 일일이 계산하기 어려워 포기하곤 했습니다.

- **계획의 어려움:** 마트 전단지나 인터넷 최저가를 일일이 찾아보며 예산을 짜는 것은 번거롭고, 영양 성분까지 고려하여 식단을 구성하기란 일반인에게 너무 높은 진입장벽이었습니다.
- **정보의 파편화:** 레시피 사이트, 가격 비교 사이트, 영양 정보 사이트가 다 따로 놀아, 한곳에서 통합적으로 식단을 '설계'할 수 있는 도구가 부재했습니다.
- **초보 개발자의 도전:** 개발 부트캠프를 통해 학습한 기술을 단순 실습에 그치지 않고, 실제 사용자가 가치를 느낄 수 있는 완성도 높은 서비스로 구현해내고 싶었습니다.

따라서 <strong>"사용자가 직접 예산과 재료를 고르면, 시스템이 가격과 영양을 분석해 스마트한 계획 수립을 도와주는 도구"</strong>를 만드는 것을 목표로 했습니다.

## 목표

- 사용자가 예산·기간·지역을 설정하면, 그 범위 안에서 식재료와 레시피를 선택하여 식단을 짤 수 있는 UI 구현
- 텍스트 위주의 공공데이터(시세, 영양소)를 그래프와 차트로 시각화하여 사용자의 의사결정 지원
- 복잡한 입력 과정을 단계별로 유도하는 직관적인 UX(Wizard Form) 설계
- Vue.js SPA 구조를 바닥부터 직접 설계하며 프론트엔드 개발의 A to Z 체득

## 나의 기여

### 1) 데이터 중심의 UI/UX 디자인 및 설계 (Design & Planning)

기획 단계에서부터 개발자이자 디자이너로서 참여하여, 데이터가 많은 서비스의 복잡도를 낮추는 데 주력했습니다.

- **계획 중심의 대시보드:** 캘린더 형태의 식단표와 장바구니 예상 금액을 한 화면에 배치하여, 사용자가 메뉴를 담을 때마다 예산 현황을 실시간으로 파악할 수 있도록 설계했습니다.
- **반응형 디자인:** 다양한 디바이스 환경을 고려하여 PC와 모바일에서 모두 최적화된 화면을 직접 디자인하고 구현했습니다.

### 2) 외부 공공데이터 통합 및 시각화 (Visualization)

서로 다른 형태의 Open API 데이터를 사용자 친화적인 정보로 가공했습니다.

- **영양 밸런스 차트:** Chart.js를 활용해 사용자가 구성한 식단의 탄단지(탄수화물·단백질·지방) 비율과 비타민 섭취량을 시각화하여, 영양 불균형을 스스로 인지하고 수정할 수 있게 도왔습니다.
- **물가 변동 추이:** KAMIS API를 연동하여 주요 식재료의 실시간 가격 등락을 그래프로 보여주어, 사용자가 "지금 사면 싼 식재료"를 판단하여 합리적인 소비를 하도록 지원했습니다.

### 3) 사용자 주도형 식단 설계 기능 구현

- **스마트 검색 및 필터링:** 식품안전나라의 1,000여 개 레시피 중 사용자가 원하는 재료나 예산 범위에 맞는 메뉴를 쉽게 찾을 수 있도록 필터링 기능을 구현했습니다.
- **인터랙티브 캘린더:** 드래그 앤 드롭과 모달을 활용하여 주간 식단표에 메뉴를 추가/삭제하고, 즉시 예산 변동을 확인할 수 있는 직관적인 인터페이스를 개발했습니다.

## 문제 해결

### 1) 파편화된 외부 API 데이터 구조 통일

- **문제:** 식재료 시세(KAMIS)와 레시피(식품안전나라) API의 응답 구조와 키값이 상이하여, 프론트엔드에서 이를 그대로 사용하기엔 렌더링 로직이 복잡해짐.
- **해결:** API 응답을 받아 컴포넌트가 사용하기 편한 표준 객체로 변환하는 '데이터 전처리 어댑터(Adapter) 함수'를 구현. 이를 통해 데이터 소스가 바뀌더라도 UI 코드는 영향을 받지 않도록 구조화함.

### 2) 과도한 정보 입력으로 인한 사용성 저하

- **문제:** 식단 계획을 위해 설정해야 할 정보(신체 치수, 예산, 목표, 기피 음식 등)가 많아, 한 페이지에 나열할 경우 사용자가 압도감을 느낌.
- **해결:** 입력 과정을 여러 단계로 쪼개어 보여주는 'Step-by-Step(Wizard)' 방식을 도입. 진행률(Progress Bar)을 표시하고 불필요한 항목은 기본값을 적용하여 입력 피로도를 대폭 낮춤.

### 3) 텍스트 데이터의 가독성 문제

- **문제:** 영양 성분이나 가격 변동 같은 수치 데이터를 표(Table)로만 보여주니 직관적인 이해가 어려움.
- **해결:** "데이터는 텍스트보다 그림이 강하다"는 원칙하에 핵심 지표를 모두 차트(Chart)와 카드 UI로 변환. 중요한 정보(예: 예산 초과 경고)는 색상을 통해 즉각적으로 인지할 수 있도록 개선.

## 성과 및 영향

- **공개 SW 개발자 대회 동상 수상:** 신입 개발자의 프로젝트임에도 불구하고 기획의 실용성과 UI/UX의 완성도를 인정받아 공식적인 성과를 거둠.
- **프론트엔드 올라운더 경험:** 기획부터 디자인, 개발, 배포까지 웹 서비스 제작의 전 과정을 홀로 수행하며, 각 파트 간의 유기적인 연결 관계를 깊이 이해함.
- **데이터 시각화 역량 확보:** 단순 CRUD를 넘어, 데이터를 가공하고 시각화하여 사용자에게 인사이트를 제공하는 프론트엔드 개발의 매력을 체감.

## 배운 점

- **완성도에 대한 집착:** "기능만 돌아가면 된다"는 안일함에서 벗어나, 디자인 디테일과 사용자 경험이 서비스의 가치를 결정한다는 것을 배웠습니다.
- **사용자 주도성의 가치:** 시스템이 일방적으로 정해주는 것보다, 사용자가 데이터를 보고 직접 판단하게 돕는 도구가 더 유용한 경험을 줄 수 있음을 깨달았습니다.
