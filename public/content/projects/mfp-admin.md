## 서비스 성격

건강검진 데이터를 기반으로 맞춤형 식품 처방(메디푸드)을 제공하는 헬스케어 플랫폼입니다. 전자정부프레임워크 기반의 서버 환경 위에서, React를 도입하여 <strong>내부 운영팀을 위한 관리자(Admin)</strong>와 <strong>병원 고객사를 위한 통계 대시보드(SaaS)</strong>를 하나의 시스템으로 통합 구축한 B2B 웹 서비스입니다.

## 나의 역할

- **React 기반 SPA(Single Page Application) 아키텍처 설계 및 개발**
- 사용자 권한(Admin/Hospital)에 따른 화면 분기 및 데이터 접근 제어(RBAC) 구현
- [SaaS] 병원용 데이터 통계 및 시각화 대시보드 **UI 구현 및 로직 개발**
- [Admin] 디자인 리소스 부재 상황에서 **관리자 페이지 UI/UX 주도적 기획 및 설계**

## 배경 및 문제

서비스 확장으로 인해 운영팀과 병원 고객사 모두를 위한 웹 시스템이 필요했습니다. 하지만 두 영역의 개발 환경과 요구사항이 상이하여 다음과 같은 과제가 있었습니다.

- **기술적 전환의 필요성:** 기존 JSP/jQuery 방식은 복잡한 데이터 시각화(SaaS)와 유연한 권한 관리를 구현하기에 한계가 있어, React 기반의 모던 웹 환경 도입이 시급했습니다.
- **리소스 불균형:** 병원용 SaaS는 디자이너의 상세한 시안이 있었으나, 내부 운영팀이 쓰는 Admin은 디자인 리소스가 배정되지 않아 개발자가 직접 사용성을 고민하고 화면을 구성해야 했습니다.
- **보안 및 권한 분리:** 하나의 도메인에서 '운영팀(모든 데이터 관리)'과 '병원(자사 데이터 조회)'이라는 서로 다른 권한을 안전하게 분리해야 했습니다.

따라서 <strong>"SaaS 영역은 디자이너의 시안을 완벽하게 구현하여 고객 만족도를 높이고, Admin 영역은 개발자 주도로 실용적인 UX를 완성"</strong>하는 것이 목표였습니다.

## 목표

- React를 도입하여 컴포넌트 재사용성을 높이고 유지보수가 용이한 SPA 환경 구축
- 로그인한 유저의 권한(Role)에 따라 메뉴 접근과 데이터 스코프를 철저히 분리하는 로직 구현
- [SaaS] 디자이너의 의도를 100% 반영한 데이터 시각화(Chart) 및 대시보드 구현
- [Admin] 디자이너 없이도 운영팀이 효율적으로 업무를 처리할 수 있는 직관적인 UI 표준 마련

## 나의 기여

### 1) React 도입 및 모던 프론트엔드 환경 구축 (Technical Challenge)

팀 내 최초로 React를 실무에 도입하여, 기존 명령형(jQuery) 방식을 선언형(Component) 아키텍처로 전환했습니다.

- **컴포넌트 시스템화:** 버튼, 폼, 테이블, 모달 등 공통 UI 요소를 모듈화하여 Admin과 SaaS 양쪽에서 개발 생산성을 높였습니다.
- **SPA 구조 확립:** 페이지 이동 시 불필요한 새로고침 없는 구조를 구현하여 쾌적한 사용자 경험을 제공했습니다.

### 2) 권한(Role) 기반의 보안 및 라우팅 설계

단일 프로젝트 내에서 운영자와 병원 담당자가 공존할 수 있는 안전한 구조를 설계했습니다.

- **동적 라우팅 및 메뉴 렌더링:** 서버로부터 받은 권한(Role) 정보를 바탕으로 접근 가능한 GNB/LNB 메뉴와 라우팅 경로를 동적으로 생성하여 보안 사고를 원천 차단했습니다.
- **데이터 격리:** 병원 계정으로 접속 시, API 호출 단계에서 해당 병원 ID를 강제 주입하여 타 병원 데이터 노출을 방지했습니다.

### 3) [SaaS] 고품질 데이터 시각화 및 비즈니스 로직 구현

디자이너가 설계한 시안을 바탕으로, 데이터가 주는 가치를 극대화하는 UI를 구현했습니다.

- **통계 대시보드 구현:** Chart 라이브러리를 활용해 환자들의 검진 데이터(BMI, 혈압 등) 분포와 서비스 이용 현황을 시각화했습니다. 디자이너가 의도한 인터랙션과 컬러 시스템을 정확히 반영했습니다.
- **리포트 자동화 처리:** 프론트엔드에서 HTML을 PDF로 변환하는 복잡한 로직을 처리하여, 병원 담당자가 즉시 리포트를 다운로드할 수 있는 기능을 완성했습니다.

### 4) [Admin] 개발자 주도의 실용적인 UX 설계

디자인 시안이 없는 Admin 영역은 사용자의 입장에서 직접 워크플로우를 설계했습니다.

- **업무 효율 중심의 UI 구성:** 운영팀의 반복 업무 패턴을 분석하여, 불필요한 페이지 이동을 줄이는 모달 기반 편집 기능과 직관적인 필터링 UI를 직접 고안하고 적용했습니다.

## 문제 해결

### 1) 이질적인 개발 요구사항의 조율 (Design vs Function)

- **문제:** SaaS는 '심미성과 디테일한 디자인 구현'이 중요했고, Admin은 '빠른 기능 개발과 사용성'이 중요하여 개발 접근 방식이 달라야 했음.
- **해결:** 공통 컴포넌트(테이블, 버튼 등)는 공유하되, SaaS는 스타일 커스터마이징이 용이하도록 유연하게 설계하고, Admin은 미리 정의된 레이아웃 패턴을 빠르게 조립하는 방식으로 개발 전략을 이원화.

### 2) 기획과 디자인의 공백 메우기 (Admin)

- **문제:** Admin 페이지는 상세 디자인 없이 기능 명세만 존재하였음.
- **해결:** 개발자가 직접 프로토타입을 그려 운영팀과 소통. "주문 상태 변경은 드롭다운보다 탭이 더 빠르다"는 식의 실사용 피드백을 통해, 디자인 리소스 없이도 사용하기 편한 시스템을 구축.

### 3) React 초기 도입에 따른 러닝 커브 극복

- **문제:** 첫 React 도입 프로젝트로서 상태 관리와 라이프사이클 최적화에 대한 시행착오 존재.
- **해결:** Props Drilling 방지를 위한 전역 상태 관리 도입, 불필요한 렌더링 방지를 위한 메모이제이션 적용 등 학습과 실무 적용을 병행하며 안정적인 성능을 확보.

## 성과 및 영향

- **성공적인 기술 스택 전환:** 기존 프레임워크 환경에서 React 기반의 독자적인 프론트엔드 영역을 구축하여 기술적 토대 마련.
- **역할에 따른 최적화된 결과물:** SaaS는 고객 만족도가 높은 고품질 UI로, Admin은 업무 효율을 극대화하는 실용적 UI로 완성.
- **주도적인 문제 해결 능력 입증:** 디자인이 있는 곳은 '정확한 구현력'을, 없는 곳은 'UX 기획력'을 발휘하여 올라운더로서의 역량 확인.

## 배운 점

- **상황에 맞는 유연한 태도:** 디자이너와의 협업에서는 '디테일한 구현'이, 리소스가 없는 환경에서는 '사용자를 위한 제안'이 중요하다는 것을 체득했습니다.
- **기술의 목적:** React 도입 자체가 목표가 아니라, 이를 통해 복잡한 권한 분리와 데이터 시각화를 효율적으로 해결하는 과정이 진짜 엔지니어링임을 배웠습니다.
